# The harness

This repo is built with coding agents, mostly Claude Code. The harness is everything
around the code that steers the agent and checks its work before a human reviews a diff:
instructions it reads, hooks that run whether it remembers to or not, skills that encode
the right procedure, and gates that fail loudly.

The server is part of a harness too: its tool schemas, descriptions, and error messages
are the instructions a *different* model (the one calling the tools) works from. So
both halves are here.

Each entry says what the file is, why it exists, and which class of agent error it catches.

## Layer 1: Instructions (what the agent is told)

| File | What it is | Why it exists | Catches |
| --- | --- | --- | --- |
| [`AGENTS.md`](AGENTS.md) | Commands, layout, and nine rules, in agent-neutral form | One source of truth any agent (Claude, Codex, Cursor, ...) can read | Agents guessing the test runner, writing to stdout, inventing error formats, adding a tool without tests or docs |
| [`CLAUDE.md`](CLAUDE.md) | `@AGENTS.md` import plus the Claude-only hooks, permissions, and skills | Claude Code loads `CLAUDE.md` automatically; importing avoids two drifting copies | The agent not knowing a hook will block it, then fighting the hook instead of fixing the cause |
| [`openspec/`](openspec/) and `.claude/commands/opsx/`, `.claude/skills/openspec-*` | OpenSpec change workflow: proposal → design → specs → tasks, generated by the OpenSpec CLI | Forces a written design and a checklist before code on anything non-trivial | Agents jumping to implementation, scope creep, "done" without each task verified |
| [`docs/discovery-notes.md`](docs/discovery-notes.md) | Dated discovery log: what was probed, measured, decided, and why | Gives the agent the *reasons* behind constraints, which code cannot carry | Agents "optimising" away a deliberate decision, e.g. caching URLs to save quota |

## Layer 2: Skills (how to do recurring tasks right)

| File | What it is | Catches |
| --- | --- | --- |
| [`.claude/skills/add-mcp-tool/SKILL.md`](.claude/skills/add-mcp-tool/SKILL.md) | Procedure: strict schema → failing contract test → implementation → README | Tools shipped with a loose schema (unknown keys silently ignored, unbounded inputs), no output schema, a test written after the code that never failed, or no docs |
| [`.claude/skills/verify-change/SKILL.md`](.claude/skills/verify-change/SKILL.md) | Full gate (lint, typecheck, tests incl. integration and stdio, audit) plus privacy checks and a reporting format | "Tests pass" claimed after running a subset; a failing gate summarised as green; skips going unnoticed |

## Layer 3: Hooks and permissions (enforced, not requested)

Configured in [`.claude/settings.json`](.claude/settings.json). Hooks run on every
matching event regardless of what the agent intends.

| File | Event | What it does | Catches |
| --- | --- | --- | --- |
| [`.claude/hooks/verify-on-stop.mjs`](.claude/hooks/verify-on-stop.mjs) | `Stop` | If build-relevant files changed, runs `typecheck` and `test`. On failure, blocks the agent from finishing and feeds back only the failing lines. After 3 consecutive blocks it lets the agent stop and tells the human. | Declaring done with a red build; "I'll fix the tests later". The 3-attempt cap stops an agent that cannot fix something from looping forever, or quietly deleting the test to escape. |
| [`.claude/hooks/privacy-guard.mjs`](.claude/hooks/privacy-guard.mjs) | `PreToolUse` (Write, Edit, Bash) | Denies writes into `.cache/` or of `*.fit`/`*.geojson`; denies `git add --force`; at `git commit`, denies staged GPS files or added real-looking COROS URLs | Committing the GPS cache past `.gitignore`; pasting a real bearer URL into a fixture or doc. These leaks are **permanent**: the URLs cannot be revoked. |
| `permissions.deny` in `settings.json` | Read | Blocks reading `.cache/**`, `*.fit`, `*.geojson`, `.env*` | Real home-adjacent GPS being pulled into the model context, where it may be logged or retained |
| `permissions.allow` in `settings.json` | Bash | Pre-approves the gate commands | Agents skipping verification because each run needs a permission prompt |

## Layer 4: Static gates

| File | What it enforces | Catches |
| --- | --- | --- |
| [`tsconfig.json`](tsconfig.json) | `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `erasableSyntaxOnly` | Unchecked array indexing (common in geometry loops), type-only import mistakes |
| [`eslint.config.js`](eslint.config.js) | typescript-eslint `strictTypeChecked`; in `src/`, `no-console` and no `process.stdout` | Floating promises (lost errors), `any` leaking from untyped APIs, and the stdio-specific bug: one `console.log` corrupts the JSON-RPC stream. Each disabled rule has its reason inline. |
| `package.json` scripts | `check` = lint + typecheck + test; `audit` = high+ | Running only the convenient subset |

## Layer 5: Tests

All tests run on `node:test` against compiled output and never touch the network.

| File | Kind | Catches |
| --- | --- | --- |
| [`test/contract-ingest-activities.test.ts`](test/contract-ingest-activities.test.ts), [`test/contract-find-routes.test.ts`](test/contract-find-routes.test.ts) | Contract, via a real MCP client | Schema loosening (each bound and unknown keys tested), output drifting from `outputSchema`, exceptions escaping as stack traces, URLs echoed in validation errors |
| [`test/integration.test.ts`](test/integration.test.ts) | In-process integration: list tools, ingest → find_routes on synthetic FIT files | A tool added without title/description/per-param descriptions/outputSchema/annotations; a new tool not wired into the integration test (the exact-tool-list assertion fails); regressions in the end-to-end grouping |
| [`test/stdio-smoke.test.ts`](test/stdio-smoke.test.ts) | Spawns the built `dist/src/index.js` over real stdio | Stray stdout writes, broken entry point, startup crashes, config validation not wired in. In-process tests cannot see any of these. |
| [`test/leak-prevention.test.ts`](test/leak-prevention.test.ts) + [`test/helpers/leak-detector.ts`](test/helpers/leak-detector.ts) | Scans logs, cache files, filenames, and tool output after a real ingest, with a negative control proving the detector fires | Any code path that logs or persists a bearer URL or a coordinate |
| [`test/hooks.test.ts`](test/hooks.test.ts) | Drives both hooks against throwaway git repos | A guard that silently stops guarding; the Stop hook's loop cap regressing |
| `test/routes-pipeline.test.ts`, `test/fetch-*.test.ts`, `test/ingest-batch.test.ts`, `test/config.test.ts`, others | Unit | Geometry invariants (direction-agnostic grouping, RDP deviation bound, determinism), SSRF policy, size caps, retry classification, deadline/resume, config bounds |
| [`test/helpers/mcp-harness.ts`](test/helpers/mcp-harness.ts), [`test/helpers/fixture-server.ts`](test/helpers/fixture-server.ts), [`test/helpers/fit-fixtures.ts`](test/helpers/fit-fixtures.ts) | Test infrastructure | Synthetic, integrity-valid FIT files keep real GPS out of the repo while still exercising the production decoder |

## Layer 6: CI

| File | What it does | Catches |
| --- | --- | --- |
| [`.github/workflows/ci.yml`](.github/workflows/ci.yml) | On every push and PR: `npm ci`, lint, typecheck, test on Node 22 and 24; `npm audit --audit-level=high` | Anything the local hooks missed, e.g. an agent session without hooks, a human commit, or a non-Claude agent. Read-only token, job timeouts. |

## The server as harness

What the *calling* model sees, and the error each part prevents:

| Where | Mechanism | Catches |
| --- | --- | --- |
| `src/tools/*.ts` input schemas | `z.strictObject`, bounded numbers, strings and arrays, `.describe()` on every field | A model guessing `target_miles`, passing kilometres as miles, or sending 10,000 URLs |
| `src/tools/*.ts` output schemas | `outputSchema` validated by the SDK on every call | Result shape drifting from what the docs and the calling model expect |
| Tool descriptions and server `instructions` | Say which tool is free, which costs quota, and what to call next | Spending the 50-file daily COROS quota on the wrong activities |
| `src/tools/errors.ts` | `{code, message, retryable}`; messages say what to do | A model retrying a permanent error, or giving up on a retryable one |
| `ingest_activities` outcomes | Per-item `status`, `reason`, `retryable`; `deadlineReached` | One bad URL failing the batch; client timeouts losing completed work |
| `src/config.ts` | Bounded env vars, fail fast at launch | A typo'd tuning value silently merging every run into one route |
